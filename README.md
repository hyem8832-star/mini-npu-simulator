# Mini NPU Simulator

MAC(Multiply-Accumulate) 연산으로 3×3 ~ 25×25 패턴이 Cross(십자가)인지 X인지 판별하는 Python 콘솔 앱입니다.

## 실행 방법

```
python main.py
```

- Python 3.8+ / 표준 라이브러리만 사용 (NumPy 등 없음)
- `1` 선택: 3×3 필터 A, B와 패턴을 한 줄씩(공백 구분) 입력 → 점수·시간·판정 출력
- `2` 선택: 같은 폴더의 `data.json`을 읽어 일괄 판정 + PASS/FAIL + 성능 표 + 요약 출력
- `data.json`은 과제에서 제공된 파일(5×5, 13×13, 25×25 필터 + 패턴 6개)입니다.

## 구현 요약

- **라벨 정규화**: `normalize_label()`이 `+`/`cross` → `Cross`, `x` → `X`로 통일. 출력과 PASS/FAIL 비교는 모두 표준 라벨 기준.
- **MAC**: 이중 for문으로 `pattern[i][j] * filter[i][j]`를 누적 (`mac()`).
- **동점 정책**: `abs(a - b) < 1e-9`이면 `UNDECIDED`. UNDECIDED는 expected와 다르므로 FAIL.
- **입력 검증**: 모드 1은 줄당 개수/숫자 파싱 오류 시 안내 문구 후 재입력. 모드 2는 스키마·크기 오류를 케이스 단위 FAIL로 처리해 프로그램이 중단되지 않음.
- **보너스(패턴 생성기)**: `make_cross(n)`, `make_x(n)`로 N×N 패턴 생성, 성능 분석에 재사용.

## 결과 리포트

### 실패 원인 분석
실행 결과: 총 6개 / 통과 3개 / 실패 3개. 실패 3건(`size_5_1`, `size_13_2`, `size_25_1`)은 모두 **수치 비교 문제(동점 → UNDECIDED)** 입니다.
스키마/라벨 문제나 크기 불일치는 없었고, 로직 오류도 아닙니다. 필터와 패턴 크기는 모두 일치했고 라벨 정규화(`+`→Cross, `x`→X)도 정상 동작했습니다.
- `size_5_1`: Cross 0.9 vs X 0.8999999999999999. 실제로는 같은 값(0.9)인데 부동소수점 누적 순서 때문에 미세하게 달라졌습니다.
- `size_25_1`: Cross 4.9 vs X 4.899999999999999. 같은 이유입니다.
- `size_13_2`: Cross 7.499999999999997 vs X 7.5. 같은 이유입니다.
세 경우 모두 |A-B| < 1e-9 이므로 epsilon 정책에 따라 동점(UNDECIDED)으로 처리했고, expected(X 또는 Cross)와 다르므로 FAIL입니다.
만약 epsilon 없이 `>`로만 비교했다면 오차 때문에 우연히 Cross/X 한쪽이 선택되어 결과가 실행 환경이나 연산 순서에 따라 달라졌을 것입니다.
즉 이 FAIL은 버그가 아니라, 점수가 사실상 같아 판정이 불가능한 데이터를 정책대로 정직하게 UNDECIDED로 보고한 결과입니다.
나머지 3건은 점수 차가 커서(예: 8.9 vs 0.1, 0.3 vs 14.7) epsilon과 무관하게 PASS입니다.
실패 진단은 (1) 데이터/스키마, (2) 로직, (3) 수치 비교 순으로 분리했고, 이번 3건은 (3)에 해당합니다.

### 시간 복잡도 분석
MAC은 N×N 칸을 한 번씩 곱하고 더하므로 연산 횟수가 N²이고, 시간 복잡도는 **O(N²)** 입니다. 3×3은 9회, 25×25는 625회로 약 69배 늘어납니다.
측정 결과(10회 평균, 실행 환경과 시점에 따라 달라짐)는 다음과 같습니다.

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|------|--------------|---------------|
| 3×3 | 0.0023 | 9 |
| 5×5 | 0.0073 | 25 |
| 13×13 | 0.0404 | 169 |
| 25×25 | 0.1427 | 625 |

크기가 커질수록 시간이 증가하는 경향은 N²과 일치합니다. 다만 증가폭이 연산 횟수 증가폭과 정확히 같지는 않은데(예: 13→25는 연산 3.7배, 시간 약 3.5배),
N이 작을 때는 함수 호출·타이머 같은 고정 오버헤드와 측정 잡음이 큰 비중을 차지하기 때문입니다.
실제 NPU는 이 N²번의 곱셈을 병렬로 처리해 시간을 줄이는 하드웨어입니다.
